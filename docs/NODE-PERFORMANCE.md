# Node 请求路径优化

目标：保持 Keala 公开 API、路由优先级、安全边界与生命周期语义，降低普通请求实际执行的工作；以 Node 26 / Bun 1.4.4 的 Hello World 和完整 12 路由逐项验证与 Hono / H3 的差距。允许内部重构，尚未证明“所有场景领先”。

基线：`f14940b`，源码摘要 `05df8d2775e7fe59d944cde7cac74f7462db566292d262d413621b0319a2ba4a`。服务器既有结果在 `bench/framework-compare/wr-2026-11-01`，本次不得覆盖。新的本地冻结副本在本次专属临时目录，结束后归档必要证据并删除。

## 分层决策

| 层                 | 当前实际工作                                                                      | 候选调整                                                                                                        | 保留与验证                                                                               |
| ------------------ | --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Node wire 生命周期 | 每请求 close 回调、Set、socket 监听注册和删除，包括同步完成的正文                 | 原生 HTTP 已绑定响应按连接记录，drain 时才观察未完成输出；未绑定的 pipeline、自定义响应和其他传输保留逐响应跟踪 | drain、背压、断连 signal、流水线未开始的响应、deadline/遗弃请求体、custom ServerResponse |
| Node 分发          | 每请求创建 answer/fail/envelope 闭包；Promise 包装跨多层                          | 错误与发送策略固定在服务级；仅异步分支捕获请求状态                                                              | onServeError、物理写失败与准备失败、绝对 request-target、HTTP/2                          |
| 请求/响应对象      | NativeRequestSource、Context、ResponsePlan；部分热路径仍有默认 init 和 tuple 分配 | 保留延迟物化，减少可证明无用的默认对象、扫描和字段访问                                                          | 原生 Request/Response 全局、Header/bytes 所有权、HEAD/空状态、池化及晚写                 |
| 路由算法           | 静态 Map → 少量前缀扫描 → 表级正则 → 语义 trie；再按方法选择编译链                | 比较注册时派生的快速入口、方法选择和动态索引，按规模选择算法                                                    | 动态注册失效、静态遮蔽、编码路径、重复参数、ALL/HEAD/405、middleware 与 param middleware |

不把采样比例直接等同于因果 CPU 节省，不为固定基准路径生成特殊实现。

## 已实施与裁决

- 默认真实 `node:http.Server` 的已绑定原生响应，每请求只更新连接引用，每连接记录至多一份最新响应，连接关闭时移出跟踪集合。`c.signal` 首次读取才安装取消监听；晚观察已断连接会回放，成功结束后晚观察不误中止。HTTPS、HTTP/2、自定义 ServerResponse 和 Bun 的 Node shim 保留兼容路径。
- 排队响应的提前 `close` 不具有 FIFO `finish` 的证明力，因此保留逐响应计数与 socket 兜底；按连接记录 queued 数量，关闭时不会因一个连接排队而留下其他空闲连接。
- drain 按 `writableFinished` 保护缓冲输出。同步调用一次 HTTP `close()` 时临时采用严格 idle 清理，finally 恢复原属性描述符；由 HTTP 自行清理请求超时间隔，避免两次原生 close 事件。不可替换的用户属性或禁止扩展的实例沿用原关闭合同。新增回归确认旧实现会截断暂停读取客户端的大正文，本次修正默认传输的这一关闭边界。
- Node 的 answer/fail/envelope、核心直接分发的结果分类改为稳定共享函数，仅异步 continuation 捕获请求状态；移除原来重复的同步/异步分类实现。
- ResponsePlan 无 init 支路不再分配空对象；URL 拆分使用原生分隔符查找，保留 path/query/fragment 语义。
- 拒绝把 `writableEnded` 当发送完成：Node 26 的 `writableFinished` 在同步 `end()` 返回时命中率为 0/75,111，不能据此跳过生命周期。
- 静态匹配已经为 O(1) Map。路由算法审查同时评估了方法执行槽、纯桶共享前缀计划及 Context 构造器；不会在尚未量化收益时替换语义 trie。有限 NativeSource 完整 dispatch 原型中，固定热点槽构造器仅节省约 2–6 ns，排除了 HTTP、admission 和原生流消费，不能外推为服务器吞吐提升；本轮先保留现有 Context 布局与路由算法。
- 已实现并撤销一个受限小表捕获计划原型：179 项路由/属性测试和独立 76 次 trie 差分通过，但同 API 微测中多数动态路径比原生整表正则更慢。正确性通过不等于性能改善，因此未纳入候选，也没有修改正式 HTTP 数据来掩盖这一结果。原来的 regex 覆盖守卫已恢复。
- 已撤销响应头字面量与数值长度原型。隔离运行的四对 A/B 配对中位吞吐 −0.45%、CPU +0.98%，两对改善、两对退化，没有稳定收益。另一次与测试进程重叠的试验整批标为受干扰，原始数据仍归档，未用于裁决。

本地第一阶段传输重构 4 对 A/B：配对中位吞吐 +7.3%、CPU/请求 −6.4%，4 对方向一致；独立中位数比为 +6.0%/−5.3%。仅为阶段证据，最终连接级候选与服务器结果另存，不能混用。

## 实施顺序与门禁

1. 冻结优化前源码与构建产物；重用现有 inspector、负载池和 CPU 快照，定位与对照成本。
2. 先完成同步 Node 发送的垂直切片，运行真实 HTTP、断连、背压、drain、自定义响应回归，再用未开启 profiler 的 A/B 衡量。
3. 依据分层证据继续优化核心对象与路由算法；复用路由微测和规模测试，跨场景核对，不能用删除慢样本或修改有效期望制造通过。
4. 按项目执行 format、lint、类型、完整 Node/Bun 测试、覆盖率、构建、进程/runtime/soak 检查；生命周期与架构由只读审查者独立核对。
5. 服务器只上传本地构建，继续使用独立临时目录与 systemd 资源配额，逐服务测试；沿用先前的安全清理协议。最终保留相同参数的原始结果与性能局限，并逐场景报告未达到领先的项目。

## 第二阶段：原生负载与核心路径（2026-11-01）

本轮与上段旧 autocannon 分开归档，不能直接算百分比。新增原生 Go HTTP/1.1 客户端：50个连接、复用预热连接、逐响应校验、3秒窗口后排空并按实际时间计量。服务端固定CPU0，客户端及协调进程固定CPU1；整个cgroup仍限150%CPU，period改为10ms。所有进程实测配额/亲和性写入原始结果。

源码与数据链在 `bench/framework-compare/all-win-2026-11-01/README.md`。保留了 app-bound Context 构造器、分发/错误冷路径拆分、uncapped settle、连接状态WeakMap、URL直接填槽、thin sugar与稳定serve策略。仍执行 Response instanceof/status/body 检查；不能用sugar标记跳过用户可修改的Response。Bun手动srvx桥接保留公开扩展而消除多余Promise包装；最终Xi只复用私有descriptor容器，重入保护与finally清理保证独立runtime和IP闭包。

被拒绝的四个原型及原因另存：原生路由延迟URI；响应身份免检；延迟原始Request扩展；suffix分组。最后一项多数路由微测退化；延迟扩展则在上游绑定Bun.serve包装层出现明确行为差异。没有靠修改行为期望或删除慢样本保留它们。

最终候选Xi源码摘要：`33f23a18be16853fdaa06371aee662a1138723e229b0e9fac06d02c0b82b2067`，A/B对照为本节起点290a。完整Node/Bun共3009项，Node2984通过25条件跳过，Bun2916通过93条件跳过；覆盖率statements95.25%、branches91.09%、functions95.94%、lines97.08%。构建、format/lint/typecheck、smoke/examples、四项进程检查、runtime合同、Node/Bun内存soak通过。路由静态Map短路径与descriptor复用由独立只读审查确认未发现正确性问题；微测不外推为HTTP收益。

## 第三阶段：因果诊断与 A/A 校准

后续证据见 `bench/framework-compare/causal-2026-11-01/README.md`。产品仍为 Xi，未采用不兼容消减、批量安装或函数提取候选。修正测试工具顺序覆盖：遍历全部起始位并配精确反向轮，记录实际 CPU 周期和加载入口，增加同入口 A/A 与诊断子集控制。四项控制测试在 Node/Bun 通过，完整 Node verify 2,988通过/25条件跳过。

416 样本、268 项检查、19,464,306 请求与 858 个测试子进程已独立复核，均无错误/重试/残留。Bun 扩展安装路径的消减使三个场景 CPU 下降约 6.2%–9.9%，但会改变公开 raw 扩展，未进入产品；这不是单个属性定义的独立成本估计。兼容批量安装/同步函数提取均无跨场景净收益。

旧三轮 Node POST p99 落后没有在 12 轮平衡对照复现：10ms 周期下 Keala−Hono 配对中位 −5.5ms。改成 1ms 周期反而令两者更慢，因此保留原配置。不能把先前四项独立中位数差描述为已确认的稳定代码退化，也不能把本轮局部诊断外推成全面领先。批量实验出现双方同时变慢的区段，原因未定，原始慢样本全部保留。
